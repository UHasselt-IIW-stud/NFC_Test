    What the results mean

    • Same UID on every tap: Chrome can identify this card, so the lab app can use Web NFC. The UID identifies the card, not the student; the app links the two through the QR record.
    • Card not readable: Chrome found the card but refuses it because it is not NDEF-compatible, and it gives no UID in that case. A native app, Power Apps or a USB reader can usually still read the UID.
    • UID changes between taps: the card makes up a random UID for privacy. No reader can use that UID to recognise the card.
    • Start with a control tag: scan a plain NFC sticker or tag first, if you have one. If that fails too, the problem is the phone or the page, not the student card.
    • Test several cards: cards issued in different years may use different chips. Web NFC never reads protected data on a card, such as the files a door-access system uses.
